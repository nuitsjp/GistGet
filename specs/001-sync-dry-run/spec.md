# 機能仕様: sync dry-run

**機能ブランチ**: `0001-speckit-specify`

**作成日**: 2026-05-28

**状態**: Draft

**入力**: ユーザー説明: "syncコマンドに--dry-runフラグを追加"

## ユーザーシナリオとテスト *(必須)*

### ユーザーストーリー 1 - 同期前に変更内容を確認する (優先度: P1)

ユーザーは `sync` を実行する前に `--dry-run` を指定し、ローカル環境と同期元の差分から実行予定の変更を確認できる。

**優先理由**: 同期はパッケージの追加、削除、更新、ピン変更を伴うため、実行前に影響範囲を確認できることが最も重要。

**独立テスト**: 同期元とローカル状態に差分がある状態で `sync --dry-run` を実行し、実際の変更が行われず、予定される操作と件数が表示されることを確認する。

**受け入れシナリオ**:

1. **Given** 同期元にローカル未導入のパッケージがある, **When** ユーザーが `sync --dry-run` を実行する, **Then** インストール予定として該当パッケージが表示され、実際にはインストールされない。
2. **Given** ローカルに同期元では削除対象のパッケージがある, **When** ユーザーが `sync --dry-run` を実行する, **Then** アンインストール予定として該当パッケージが表示され、実際にはアンインストールされない。
3. **Given** 同期元とローカルでバージョンまたはピン状態が異なるパッケージがある, **When** ユーザーが `sync --dry-run` を実行する, **Then** アップグレード予定またはピン変更予定として該当パッケージが表示され、実際には変更されない。

---

### ユーザーストーリー 2 - 任意の同期元でもプレビューする (優先度: P2)

ユーザーは通常の同期元だけでなく、URL またはローカルファイルで指定した同期元に対しても `--dry-run` で変更内容を確認できる。

**優先理由**: 既存の同期元指定を使うユーザーにも、実行前確認の価値を同じように提供する必要があるため。

**独立テスト**: `--url` または `--file` と `--dry-run` を同時に指定し、指定した同期元との差分が表示され、実際の変更が行われないことを確認する。

**受け入れシナリオ**:

1. **Given** URL で指定した同期元に差分がある, **When** ユーザーが `sync --dry-run --url <URL>` を実行する, **Then** URL の内容に基づく実行予定が表示され、ローカル環境と同期元は変更されない。
2. **Given** ローカルファイルで指定した同期元に差分がある, **When** ユーザーが `sync --dry-run --file <PATH>` を実行する, **Then** ファイルの内容に基づく実行予定が表示され、ローカル環境と同期元は変更されない。

---

### ユーザーストーリー 3 - 差分の有無を安定して判断する (優先度: P3)

ユーザーは `--dry-run` の結果から、変更が必要な項目と更新不要な項目の件数を確認し、実行してよいかを判断できる。

**優先理由**: 変更予定だけでなく更新不要の件数も示すことで、同期対象全体が評価されたことを利用者が確認できるため。

**独立テスト**: 差分がある場合とない場合の両方で `sync --dry-run` を実行し、予定件数と更新不要件数が表示され、コマンドが成功として終了することを確認する。

**受け入れシナリオ**:

1. **Given** 同期元とローカル状態に差分がない, **When** ユーザーが `sync --dry-run` を実行する, **Then** 変更予定がないことと更新不要件数が表示され、成功として終了する。
2. **Given** 同期元とローカル状態に差分がある, **When** ユーザーが `sync --dry-run` を実行する, **Then** 差分が表示され、実行結果は成功として扱われる。

---

### エッジケース

- 同期元が空の場合、実行予定の変更と更新不要件数が矛盾なく表示され、実際の変更は行われない。
- ローカルに同期元へ存在しないパッケージがある場合、通常同期で対象となる削除予定だけが表示され、実際の削除は行われない。
- 同じパッケージにバージョン変更とピン変更の両方がある場合、ユーザーが必要な変更を判別できる粒度で表示される。
- 差分があっても、プレビュー実行そのものは失敗扱いにならない。
- 同期元の読み込みに失敗した場合は、通常の同期と同じ扱いでエラーを表示し、変更は行われない。

## 要件 *(必須)*

### 機能要件

- **FR-001**: システムは `sync` に `--dry-run` フラグを追加し、ユーザーが同期前に変更内容をプレビューできるようにしなければならない。
- **FR-002**: システムは `--dry-run` 指定時、同期元とローカル状態を比較し、インストール予定、アンインストール予定、アップグレード予定、ピン追加または更新予定、ピン削除予定を表示しなければならない。
- **FR-003**: システムは `--dry-run` 指定時、更新不要の件数を表示しなければならない。
- **FR-004**: システムは `--dry-run` 指定時、パッケージのインストール、アンインストール、アップグレード、ピン変更を実行してはならない。
- **FR-005**: システムは `--dry-run` 指定時、同期元への保存または更新を実行してはならない。
- **FR-006**: システムは `--dry-run` と既存の同期元指定を同時に扱い、通常の同期元、URL、ローカルファイルのいずれでも同じプレビュー結果を提供しなければならない。
- **FR-007**: システムは `--dry-run` 指定時に差分が存在しても、プレビューが完了した場合は成功として扱わなければならない。
- **FR-008**: システムは `--dry-run` を指定しない既存の `sync` 動作を変更してはならない。
- **FR-009**: システムは同期元の読み込みに失敗した場合、ユーザーに失敗理由を示し、ローカル環境と同期元を変更してはならない。

### 主要エンティティ *(データを扱う機能のみ)*

- **同期元パッケージ**: 同期で期待されるパッケージ。識別子、表示名、期待バージョン、ピン状態、削除対象かどうかを含む。
- **ローカルパッケージ状態**: 現在の端末に存在するパッケージの状態。識別子、表示名、導入済みバージョン、ピン状態を含む。
- **プレビュー結果**: 同期元パッケージとローカルパッケージ状態の比較結果。操作種別ごとの対象一覧と更新不要件数を含む。

## 成功基準 *(必須)*

### 測定可能な成果

- **SC-001**: ユーザーは `sync --dry-run` の 1 回の実行で、実行予定の操作種別と対象件数を確認できる。
- **SC-002**: `--dry-run` 実行後、プレビュー対象のパッケージに対する実際の追加、削除、更新、ピン変更、同期元保存が 0 件であることを確認できる。
- **SC-003**: 通常の同期元、URL、ローカルファイルの 3 種類すべてで、同じ差分条件に対して同じ分類結果を確認できる。
- **SC-004**: 差分がある `--dry-run` 実行の成功率は 100% で、差分の存在だけを理由に失敗扱いにならない。
- **SC-005**: `--dry-run` を指定しない既存の同期シナリオは、追加前と同じユーザー向け結果を維持する。

## 前提

- `--dry-run` はプレビュー専用であり、確認後に実行する場合はユーザーが改めて通常の `sync` を実行する。
- `--dry-run` では状態確認のための読み取りは許可し、ローカル環境または同期元に変更を加える操作は禁止する。
- 出力は人が読んで判断できる形式とし、機械処理用の追加出力形式はこの機能の対象外とする。
- 既存の `--url` と `--file` の意味や指定方法は変更しない。
